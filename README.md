# Liftory

Мобильный дневник тренировок без сервера и регистрации. Упражнения, программы, подходы, история, измерения и цели сохраняются в SQLite на устройстве. На iOS изменения синхронизируются через private database CloudKit в личном iCloud пользователя. На Android приложение работает локально.

## Что работает

- 40 встроенных упражнений, поиск, фильтр и свои упражнения.
- Программа на 1–52 недели с днями отдыха, тренировками и списком упражнений.
- Готовые программы и собственные шаблоны тренировок.
- Быстрый старт и старт из программы; незавершённая тренировка восстанавливается после закрытия приложения.
- Подходы с весом, повторениями, RPE, разминкой и дроп-сетами; таймер отдыха, заметки, замена упражнения.
- История, объём, число тренировок и подходов, оценка максимума по выполненным подходам, графики веса и объёма, цели.
- Фитнес-профиль, недельный обзор и необязательная приблизительная оценка калорий и макронутриентов.
- Светлая, тёмная и системная темы.
- Нативные системные вкладки на iOS и Android; на iOS 26 система использует Liquid Glass, на старых версиях — стандартный системный таб бар.

На iOS iCloud работает после настройки App ID и контейнера и пересборки нативного приложения. Если iCloud недоступен, локальное сохранение продолжает работать. Синхронизация запускается после правок и при возвращении приложения на экран; данные из чужого iCloud Account с уже привязанной локальной базой не смешиваются.

## Запуск и проверки

```bash
npm install
npm run ios       # подписанная dev-сборка нужна для CloudKit
npm run android   # локальный режим
npm run typecheck
npm run lint
npm test -- --runInBand
```

Вход через Apple и серверный API удалены. `expo-apple-authentication`, `expo-secure-store` и `@tanstack/react-query` приложению больше не нужны. Исходники нативных проектов генерируются из `app.json` через `npx expo prebuild`.

## Настройка Apple

См. [docs/apple-icloud-setup.md](docs/apple-icloud-setup.md). Bundle ID пока оставлен прежним: `vladAstahov.gymTracker.GymTracker`. Если он зарегистрирован за другой командой, перед подписанной сборкой нужно согласованно заменить его и идентификатор iCloud-контейнера в `app.json`, модуле CloudKit и документации.

## Хранение и конфликты

`src/entities/training/store.ts` хранит записи и журнал несинхронизированных изменений в одной таблице SQLite. Каждая правка сохраняется локально до обращения к iCloud. Удаления остаются tombstone-записями, поэтому удалённые объекты не возвращаются с другого устройства. Для параллельных изменений одной записи применяется детерминированный порядок: удаление, затем локальная ревизия, затем ID устройства. Это означает, что две одновременные правки **одной** программы или тренировки могут привести к победе одной версии целиком; разные записи сливаются независимо. Встроенный каталог создаётся на каждом устройстве из исходников и в CloudKit не отправляется.

Облачный транспорт находится в `modules/liftory-cloud`. Он читает и пишет только private database контейнера `iCloud.vladAstahov.gymTracker.GymTracker`.

Расчёт энергии в профиле использует [уравнение Mifflin–St Jeor](https://pubmed.ncbi.nlm.nih.gov/2305711/) и простой коэффициент активности. Это стартовый ориентир для взрослых: реальные потребности зависят от индивидуальной динамики, как подчёркивает [NIH Body Weight Planner](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner).
